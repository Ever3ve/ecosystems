# Інструкція для учасників проєкту

## 1. Правила роботи з гілками

- Гілка `main` містить стабільну версію проєкту.
- Для кожної нової функції, виправлення помилки або зміни документації створюйте окрему гілку.
- Називайте гілки зрозуміло, відповідно до їхнього призначення:
  - `feat/add-operation` — додавання функціональності;
  - `fix/division-error` — виправлення помилки;
  - `docs/update-user-guide` — зміна документації.

## 2. Правила оформлення комітів

У проєкті використовується стандарт Conventional Commits.

Основні типи комітів:

- `feat:` — додавання нової функції;
- `fix:` — виправлення помилки;
- `docs:` — зміни документації;
- `test:` — додавання або оновлення тестів;
- `refactor:` — зміна структури коду без зміни його функціональності;
- `chore:` — технічні та допоміжні зміни.

Приклади правильних повідомлень комітів:

- `feat: додати операцію відсотків`
- `fix: виправити ділення на нуль`
- `docs: додати інструкцію для учасників`

## 3. Правила створення Pull Request

1. Отримайте останні зміни з гілки `main`.
2. Створіть окрему гілку для своїх змін.
3. Внесіть зміни та створіть коміт відповідно до Conventional Commits.
4. Відправте гілку до GitHub.
5. Створіть Pull Request із цільовою гілкою `main`.
6. Додайте зрозумілий заголовок і опис змін.
7. Запросіть відповідального рев'ювера.
8. За потреби виправте зауваження після перевірки.
9. Об'єднуйте зміни в `main` після необхідного погодження.

## 4. Загальні вимоги

- Робіть зміни невеликими та зрозумілими.
- Дотримуйтеся наявної структури проєкту та стилю коду.
- Перевіряйте Markdown-файли за допомогою налаштованого лінтера.
- Перед надсиланням змін у коді перевіряйте успішність збирання проєкту командою `dotnet build`.
- Не додавайте до комітів сторонні файли, тимчасові файли та секретні дані.
