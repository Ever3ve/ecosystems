# ADR 0003: Використання CODEOWNERS для рев'ю змін

## Status

Accepted

## Context

У проєкті працює кілька учасників, і кожен відповідає за свою частину: документацію, код та інфраструктуру. Без формалізованих правил зміни можуть потрапити в `main` без перевірки профільним учасником.

## Decision

Використовувати файл `.github/CODEOWNERS`. Для кожної директорії та файлу закріплюється власник, якого GitHub автоматично додає рев'ювером до Pull Request. У захисті гілки `main` вмикається вимога схвалення від code owner.

## Consequences

- Зміни в документації, коді та інфраструктурі перевіряють відповідальні особи.
- Рев'ю маршрутизується автоматично.
- Власник, який не відповідає на PR, може блокувати злиття.
- Файл потрібно оновлювати, коли змінюється структура проєкту або склад команди.
