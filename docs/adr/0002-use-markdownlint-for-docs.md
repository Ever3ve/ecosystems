# ADR 0002: Використання Markdown-лінтера для документації

## Status

Прийнято.

## Context

У проєкті використовується Markdown для створення документації. Помилки форматування, заголовків і списків можуть погіршувати читабельність документів. Тому необхідно автоматизувати перевірку Markdown-файлів.

## Decision

Для перевірки Markdown-документації вирішено використовувати markdownlint. Перевірку файлів `.md` потрібно виконувати автоматично перед створенням коміту за допомогою налаштованих Git Hooks.

## Consequences

- Документація матиме єдиний стиль оформлення.
- Частину помилок форматування можна буде виявляти до створення коміту.
- Учасникам команди потрібно буде виправляти помилки, виявлені лінтером.
- Перевірка документації вимагатиме додаткового часу перед комітом.
